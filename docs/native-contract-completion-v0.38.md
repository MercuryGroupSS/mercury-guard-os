# Connected native contract completion — v0.38

This slice corrects recovered Mercury One requirements in the connected account flow. It does not establish physical Fold acceptance or activate an assignment.

The assignment overview no longer offers early clock-out. Before the scheduled end, **End shift early** is available only inside the assignment's **Escalate** screen and retains the existing nonblank reason and explicit confirmation. An open overview, authorized capture screen or assigned escalation screen reveals **Clock out** when its verified service epoch plus same-boot elapsed time reaches the scheduled end. This changes presentation only: time passing does not submit a transition, invent a receipt, or record attendance. Expired capture is unavailable. Navigation, inactive lifecycle, sign-out and an unresolved original transition fence the display callback. An unfinished incident editor is retained at the deadline. No background clock-out notification guarantee was added.

A route may explicitly declare `gps_required: true`; omission preserves the legacy manual route. `false`, strings and other coercions are rejected. Connected capture uses the plan-aware store entry, which independently requires the exact selected route/revision/round/checkpoint and refuses a required-GPS completion without the original consent-bound fix. A manual plan refuses a GPS payload.

The GPS action uses a separate foreground one-shot listener, not cached location or the continuous location service. The user reviews the exact approved policy notice and can record consent for patrol point fixes without starting continuous collection. Each checkpoint action requires precise permission, GPS, a current signed grant with both patrol and location authority, the same individual account/device/assignment, and the original current consent/policy. A callback must be newer than that specific request, nonmock, within approved accuracy/freshness and original grant bounds. Request, fix and observation epochs derive from the same monotonic clock and verified server anchor, not editable device wall time. The request removes only its own listener on success, explicit cancellation, pause/navigation, changed authority, provider failure or a bounded timeout (at most 20 seconds and never beyond its lease). Failure saves no checkpoint and provides no manual fallback. The immutable original notice/consent metadata follows its own withdrawal-sensitive upload partition so blocked GPS does not block ordinary incidents. Coordinates alone do not establish physical presence; approved geometry is evaluated separately by the service.

**My recorded incidents** first re-verifies the current profile and possession-authorized phone assignments. Newly captured incidents atomically retain their original local owner (configuration, installation ID/key, Auth subject, guard, vendor, site and assignment) without changing the signed event protocol. History is read-only and separates locally saved, service-accepted and retained-review states from dashboard delivery. Legacy rows lacking complete owner metadata remain encrypted and hidden. The secure host closes and scrubs the view on navigation, session changes and pause; reopening requires sign-in. Local expiry/owner checks run before render/navigation. A history view is not an assertion of immediate remote revocation detection while already open.

Local version 38 verification passed 51 JVM tests with no failures or skips, all Android test-source compilation, and preview lint with zero errors (214 warnings, one informational issue). Instrumentation execution was not performed during this source-edit slice. The new clock/filter/host tests and independent incident-history/GPS-store tests contain synthetic data; they do not claim physical GNSS, biometrics, attended camera behavior or presence. Exact-source API28/API35 instrumentation and HTTPS workflows remain the execution gate for the candidate. Physical Fold GPS delivery, permission/recovery behavior, folded/unfolded presentation and final production signing custody remain separate acceptance gates.

Android API references used for the one-shot implementation: [LocationManager update and removal semantics](https://developer.android.com/reference/android/location/LocationManager), [monotonic location timestamps](https://developer.android.com/reference/android/location/Location#getElapsedRealtimeNanos()). The minimum supported API remains 28; no new background location permission or service was introduced.
