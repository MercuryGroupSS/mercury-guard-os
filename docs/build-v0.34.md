# Mercury One Preview v0.34

This build adds connected shift-location consent and a separate foreground collector, plus durable incident-draft recovery in the individually authenticated flow. It retains any-order checkpoints and explicit patrol rounds, protected reports/private photos, encrypted original-scope delivery and operational escalation from the earlier build.

An approved assignment must supply its complete location policy and exact notice. The guard separately reviews it, checks consent and starts from a visible screen. The collector uses only a matching signed short lease, verifies the same individual/device/assignment/consent/policy on renewal, and stops on withdrawal, unavailable renewal, permission/session/shift changes or task closure. It has no persisted restart authority, sticky/reboot start or background-location permission. Device biometrics remain a local UI gate, independent of the individual Auth account.

Immutable consent order and a permanent same-scope/policy withdrawal barrier prevent an older consent from becoming eligible after a newer withdrawal. A genuinely later explicit consent authorizes only its own records. Location batches retain the original subject/configuration/device/assignment/consent/policy partition so a denied location queue cannot block independent incidents. The production collector rejects mock, stale and inaccurate fixes. An unavailable fix does not establish presence or create a geofence alert.

Incident edits now save encrypted under the original individual account, trusted configuration, installation key, vendor, site and assignment. Patrol/Escalate navigation, rotation and background/reauthentication recover the same unfinished text. A different individual cannot see it. Saving/discarding uses an exact-text check before clearing; nothing auto-submits or relabels an old draft. The old scheduled-end demo test fixture now starts its monotonic shift at the current elapsed time, separating scheduled-end behavior from an unrelated readiness deadline.
