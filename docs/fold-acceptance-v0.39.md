# Mercury One v0.40 — attended Fold additions

All physical results start **OPEN**. Use the [complete baseline Fold procedure](fold-acceptance-v0.35.md) with these additions and the current immutable APK/source records. Earlier demo, emulator and typed-location results do not establish current hardware acceptance. Do not access the phone until the user resumes physical testing.

| Check | Required observation |
| --- | --- |
| Artifact and update | Record the current configured APK hash, source commit, package and certificate. Preserve existing app data and the original application. Stop if an update requires uninstalling, clearing data or replacing the signing identity. |
| Instructions before start | As approved test guard A, open a future assigned shift and read its current instructions. No clock-in, active shift, capture grant or acknowledgement should result. End the view, sign out and sign in as B; A's text must not appear. An offline first read must report unavailable rather than displaying an unrelated cached instruction. |
| Connected readiness | Open the connected readiness panel before and during an approved shift. Record the real account/assignment and service refresh result, OS permission/channel state, consent state and location status. Refresh must provide feedback. Permission granted or requesting updates must not be presented as a fresh fix. Merely opening readiness must not start location or attendance. |
| Required-GPS checkpoint | Use a separately approved test route that requires GPS and its exact notice/consent. Select checkpoints out of order within the authorized round. Declined permission, unavailable GPS, stale/mock/inaccurate fixes or an expired grant must save no checkpoint and offer no manual fallback. An actual fresh SDK fix must retain the exact checkpoint/round/consent attribution; record its reported age/accuracy without publishing private coordinates. |
| Point request lifecycle | Start a checkpoint fix, cancel or navigate away, then background/fold and reauthenticate. No late callback may record a checkpoint. A continuous collector, if separately authorized, must not lose its own listener when the point request stops. |
| Incident history | Save one incident as A and verify its original text and truthful local/service status. Confirm it survives authorized fold/reopen without becoming B's record. Unknown-owner legacy rows must not be relabelled. A service receipt alone is not a connected Ops display acknowledgement. |
| Shift controls | Before scheduled end, find early exit inside the assignment's Escalate flow with a reason and separate confirmation. Leave the overview or an unfinished incident editor open across the trusted scheduled deadline: Clock out should appear while text remains intact. Time passing must not create attendance. Confirm clock-out explicitly and verify its receipt separately. |
| Delivery and withdrawal | Confirm original-scope GPS checkpoint retry and its service receipt, then consent withdrawal and denial of queued original location partitions. Independent incidents must remain deliverable. Verify Guard receipt, original photo-byte receipt, receiver receipt and actual approved Ops display separately. |

Retain failures or blocks with the exact build hash, private test identities and receipt IDs. An unavailable SDK fix, delayed Android job, unread permission prompt or unperformed fold is not a pass. Finish with no active test shift, collection or signed-in account, preserving original queues and evidence.

Production signing/update recovery, email transport, current guard/vendor/site/device/schedule approvals, independent Ops bindings, retention/backups/key recovery and a full-shift battery/Doze exercise remain separate gates. No firmware, device-owner enrollment or kiosk change is part of this test.
